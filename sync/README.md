# 同步记录（sync/）

每台设备一个文件，文件名用主机名，例如 `DESKTOP-4JAFHLD.md`。

## 为什么按设备分开

- 所有设备共用一份记录时，大家会反复修改同一个文件的同一区域，冲突概率最高。
- 改成每台设备写自己的文件后，**任何设备都不修改别人的文件，从根上不会冲突**。
- 因此也不需要「30 条上限」这种跨设备删除旧记录的操作。

## 什么时候写

| 情况 | 是否记录 |
| --- | --- |
| 本次任务产生了提交并推送 | ✅ 在**同一个 commit** 里追加一行 |
| 只做了 `pull` / `fetch` | ❌ 不记录 |
| 只读查看、`git status`、`git log` | ❌ 不记录 |
| 推送失败、最终没推上去 | ❌ 不记录，等真正推上去再记 |

**核心原则：记录搭便车，不自己开一班车。**

记录只在「本来就要提交」的时候顺带更新，绝不为记账单独产生一次提交。否则会出现「记录 pull 的提交 → 又变成别人要 pull 的新提交 → 别人又要记录……」的死循环。

## 格式

最新的在最上面，四列：时间 / 操作 / 结果 / 备注。

    | 时间 | 操作 | 结果 | 备注 |
    | --- | --- | --- | --- |
    | 2026-10-22 04:35 | 改造同步记录规则 | ✅ | 改成每设备独立文件 |

不设条数上限；文件太大时由本设备自行删除自己最旧的记录，不要去动别人的文件。

## 新设备接入

1. 新建 `sync/<主机名>.md`，参考现有文件的顶部「设备信息」表格填好。
2. 在 `SYNC-TEST.md` 的设备表里加一行（只在接入时改一次，不是日常操作）。
3. 不需要修改其他设备的记录文件。
