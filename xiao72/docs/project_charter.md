## 1. 长期愿景（原始需求，逐字记录）

> "做一个智能助手，识别我的语音命令，接入我的硬件，用我的函数控制我的 AI 助手专用显示器显示聊天文本 / 音箱语音输出 / 摄像头云台机械臂 / 图像识别（或用 K230 返回识别信息），帮我完成语音互动解决工程问题；利用云台机械臂和摄像头监控房间，完成物品查询、人脸识别、生物识别（猫）、记录进入次数时间和行为，利用机械臂控制加图像识别构成闭环完成桌面整理。"

## 2. 必须提前承认的边界（现在写，避免以后自我欺骗）

**R9 和 R10 是这类项目最常见的坟墓**，原因不是技术不可能，而是：

| 陷阱 | 具体表现 | 现实后果 |
|---|---|---|
| **"行为"没有定义** | "记录行为"可以是"他来了"也可以是"他在喝水" | 永远做不完，且无法验收 |
| **手眼标定被低估** | 相机坐标 → 机械臂坐标的变换，误差随距离放大 | 桌面整理需要亚厘米级精度 |
| **抓取规划不是调包** | 物体位姿估计 + 碰撞避免 + 力控 | 单这一项就是一篇论文的量级 |
| **多目标跟踪** | 猫在动、人在动、遮挡、重识别 | 学术级难度，非玩具级 |
| **实时性 vs 云端** | 云端大模型延迟 0.5–2s | 机械臂不能靠云端闭环 |

### 结论：R10（桌面整理）**现在不应作为目标**
建议降级为"未来可选实验"，且必须先满足：
1. 固定相机 + 固定臂基座的标定误差 < 5mm
2. 只整理**已知类别 + 固定摆放位置**的物品
3. 全程有人监督，有物理急停

## 3. 分阶段路线（建议，未确认）

```
阶段 A  灯控链路（进行中，已完成 v0.1）
        文本 → 意图 → 帧 → 单片机 → PWM
        目的：验证"分层 + 兜底"这套骨架

阶段 B  加安全兜底
        超时熄灭、板子 ACK、断线重连

阶段 C  换意图层 + 加语音
        规则 → LLM → ASR/TTS
        接口不变，只换输入输出

阶段 D  第一类执行器扩展：舵机
        云台 2 轴（比机械臂简单，风险可控）
        这一阶段会把"执行器抽象"真正压出来

阶段 E  视觉只做"看得见"
        摄像头画面显示 + K230 回传识别结果
        不做闭环控制，先只观察

阶段 F  闭环（谨慎）
        先做"看 → 说"，不着急"看 → 动"
```

**关键原则**：每个阶段都必须"能演示、能停止、能降级"。
不允许出现"必须整个系统跑起来才知道有没有用"的阶段。

## 4. 决定不做什么（Negative Scope）

明确写下**不做**，比写下做什么更重要：

- ❌ 不做无监督的全屋机器人（成本与安全都不现实）
- ❌ 不用云端模型做实时运动控制
- ❌ 不碰强电（220V 负载必须用成品模块 + 隔离）
- ❌ 不在没有物理急停的情况下让机械臂自动运动
- ❌ 不追求"像人一样对话"，追求"能用、可预期"
