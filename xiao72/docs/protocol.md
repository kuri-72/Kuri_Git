# 小72 · 灯控链路协议规格 v0.1（草案）

> 状态：**草案**。KURI72 说"问题还没研究明白，不需要按某种格式定死"。
> 所以本文件只做一件事：**把"帧格式"和"解析逻辑"隔离开**，将来改格式只改这一层。

---

## 1. 分层与职责（谁不许越界）

```
┌─────────────────────────────────────────────────────────────┐
│ ① 用户自然语言        "灯好亮啊"                              │
├─────────────────────────────────────────────────────────────┤
│ ② 意图识别层（LLM）   输出 JSON，不是协议文本                  │
│    唯一职责：理解人话 → 结构化意图。可能出错，可替换。          │
├─────────────────────────────────────────────────────────────┤
│ ③ 状态合并 + 协议序列化（PC 上的确定性代码）                   │
│    职责：意图 + 当前状态 → 完整状态帧。每次都一样。            │
│    ★ 这是"闸门"：AI 的废话、幻觉、多余格式在这里被丢弃         │
├─────────────────────────────────────────────────────────────┤
│ ④ 传输（串口 UART，ASCII，\n 结尾）                            │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 单片机执行层（C）    解析 → 限幅 → 状态机 → PWM             │
│    职责：最后一道物理安全防线。不信任 ①-④ 的任何输入。         │
└─────────────────────────────────────────────────────────────┘
```

**铁律**
1. AI 的输出**永不**直接进串口，必须经过 ③。
2. 单片机**永不**假设 PC 发来的东西合法。
3. 协议格式改动，**只允许**改 ③ 的 `encode` 和 ⑤ 的 `parse`，两边加同一组测试用例。

## 2. 帧格式 v0.1（临时，可换）

```
[L<bbb><ppp>|A<000>|<xxx>]
```

| 字段 | 宽度 | 含义 | 取值范围 |
|---|---|---|---|
| `[` | 1 | 帧头。未见帧头前的所有字节**丢弃** | — |
| `L` | 1 | 灯设备标志 | — |
| `<bbbb>` | 4 | 亮度 0–100，**左补零 4 位**（`0050` = 50%） | 0000–0100 |
| `<pppp>` | 4 | 呼吸周期，**单位 ms**，左补零 4 位（`2000` = 2 秒，`0000` = 常亮） | 0000–9999 |
| `|` | 1 | 段分隔符（当前只有一段，保留给多设备） | — |
| `A` | 1 | 机械臂段标志（**本版不实现，固定发 `A---`**） | — |
| `---` | 3 | 机械臂占位 | 固定 `---` |
| `<xxx>` | — | 保留段（**本版不实现**，见下） | — |
| `]` | 1 | 帧尾。**只有收到 `]` 才认为帧完整** | — |
| `\n` | — | 换行，仅方便串口助手手工调试，解析时忽略 | — |

**关于 `<xxx>`**：你原设想里还有一段"其他外设与参数"，格式未定。
本版把它做成**长度可变的保留段**，解析器遇到就跳过 —— 这样你以后加设备时，
**只要改 `parse` 里一个 `case`，不用动帧结构**。

### 具体例子

```
[L00502000|A---|]         亮度 50%，呼吸周期 2000ms
[L01000000|A---|]         常亮 100%（周期 0 = 不呼吸）
[L00000000|A---|]         熄灭
[L00720000|A---|R]        保留段里有一个 'R'，本版解析器会忽略它
```

**为什么是固定宽度 + 显式分隔符**（回答你"不同意"的理由之一）：

| 你原方案 | 风险 | 本方案 |
|---|---|---|
| `L0050B2000` 靠"L 占 4 位、B 占 4 位"隐式切分 | 丢 1 字节 → 全帧错位 → 角度/亮度乱跳 | 有长度和分隔符，**错位可被检出并整帧拒收** |
| `ang_10090` 是"舵机1=90"还是"舵机10=90"？ | 歧义无法自证 | 固定 3 位，无歧义 |
| 整帧 100+ 字节带解释 | F103 的 20KB RAM 里做缓冲很勉强 | 本帧 **17 字节**，任意缓冲都能放 |

## 3. 错误处理约定（单片机侧）

| 情况 | 动作 | 返回 |
|---|---|---|
| 帧头前收到垃圾字节 | 丢弃 | — |
| 超长（缓冲满仍无 `]`） | 清空缓冲，丢弃整帧 | `!OVERFLOW` |
| 帧不完整（超时 200ms 无新字节） | 丢弃 | `!TIMEOUT` |
| 亮度 > 100 | **限幅到 100**，不拒收 | `!CLAMPED`（可选） |
| 周期 > 999 | **限幅到 999** | `!CLAMPED`（可选） |
| 格式错误 | 保持上一帧状态 | `!FRAME` |
| 合法帧 | 应用 | `OK` |

> **限幅而不是拒收**，是因为"保持灯亮"通常比"灯突然灭"安全。
> 但**机械臂将来必须反过来**：越界一律拒收 + 停机。这条差异现在就要记住。

---

## 4. 时间基准

- 呼吸效果必须用 **非阻塞** 方式（`millis()` 累加），不能用 `Delay_ms()`。
  理由：一旦接上串口接收，`Delay_ms()` 期间收不到命令，表现为"发命令没反应"。
- 呼吸波形：三角波或正弦波，**步骤 = 周期 / 200**，保证周期参数是"真实周期"。

## 5. 测试向量（两边必须一致）

| 输入帧 | 期望状态 |
|---|---|
| `[L00502000|A---|]` | brightness=50, period_ms=2000 |
| `[L01000000|A---|]` | brightness=100, period_ms=0 |
| `[L01500000|A---|]` | brightness=100（限幅到 100）, period_ms=0 |
| `[L-1x2000|A---|]` | 拒收，状态不变 |
| `junk junk[L00300500|A---|]` | brightness=30, period_ms=500（垃圾被丢弃） |
| `[L00300500|A---` | 无帧尾，宽容接受（手工调试场景） |
| `[L00300500]` | 段数不对，拒收 |

## 6. 身份握手 v0.4（设备自报身份）

### 为什么需要

CH340 这类 USB 转串口芯片**没有唯一的 USB 序列号**，同型号两颗在系统里无法区分；
COM 口号又会随插拔顺序、驱动重装而变化。所以「哪个口是哪台设备」不能靠系统，
只能靠**设备自己说**。

### 报文

| 方向 | 内容 |
|---|---|
| PC → 设备 | `[I?]` |
| 设备 → PC | `[I <id>\|<model>\|<version>\|<cap1,cap2>]` |

例：

```
PC   →  [I?]
设备 →  [I kuri72-desk|X72-LED|1.0|led,brightness,period]
```

| 字段 | 说明 | 能否空 |
|---|---|---|
| `id` | 设备唯一名，用户自定，建议 `<房间>-<设备>` | 否 |
| `model` | 型号 | 否 |
| `version` | 协议版本 | 否 |
| `caps` | 能力清单，逗号分隔 | 否 |

### 兼容性（双向）

- **新 PC + 老固件**：老固件把 `[I?]` 当非法帧丢弃且**不回复**；PC 超时 0.6s 返回 `None`，不抛异常，不影响后续发帧。
- **老 PC + 新固件**：老 PC 从不发 `[I?]`，新固件因此永不回复，行为不变。
- 所以**升级顺序随意**，不会出现"必须同时升级"的窗口。

### 实现位置

| 文件 | 职责 |
|---|---|
| `firmware/x72_proto.h` | `X72_DEVICE_ID / X72_DEVICE_MODEL / X72_DEVICE_CAPS`，可用编译宏覆盖 |
| `firmware/x72_proto.c` | `dispatch_line()` 行首匹配 `[I` → 组应答 → 调钩子 |
| `firmware/USART1.c` | `x72_send_line()` 实现阻塞发送 |
| `host/device_id.py` | `identify_port()` / `scan_ports()`，扫描所有非蓝牙端口 |

### 注意

`x72_send_line()` 是**阻塞发送**，只在收到 `[I?]` 时调用，最长约 60 字节
（115200 下约 5ms）。不要在中段里调用；它由主循环侧的解析入口触发，不涉及中断。
